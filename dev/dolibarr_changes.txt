version, upstream's own composer.json marks TCPDF "abandoned" in favor of
tecnickcom/tc-lib-pdf - kept for now since Dolibarr (and the bundled TCPDI
fork) still relies on TCPDF-specific internals; a migration off TCPDF
entirely would be a separate, much larger effort.

this version. tcpdf_parser.php (TCPDF_PARSER) is still required by
htdocs/core/lib/pdf.lib.php::pdf_getEncryption(), so our unmodified copy of
the 6.7.5 file is kept alongside the upgraded library. tcpdf_import.php was
unused anywhere in Dolibarr and was not kept.

  allowLocalFiles defaults to false upstream (new in 6.11.4, opt-in on
  purpose - it also gates a fileExists() check for "file://" paths); Dolibarr
  enables it itself by calling $pdf->setAllowLocalFiles(true) right after
  instantiating TCPDF/TCPDI in htdocs/core/lib/pdf.lib.php::pdf_getInstance(),
  instead of hardcoding the default to true in the vendored file.

  Before 6.11.4, this same "convert file://... to a local path" behavior was
  a bespoke elseif branch inserted ahead of TCPDF's own image-src handling,
  and needed a "$reg = array();" guard to avoid a warning on an unrelated
  base64 data-URI branch. Both are obsolete: upstream now parses base64
  data-URIs natively with its own properly-scoped $reg, and now has its own
  (opt-in) file:// branch that this patch replaces the body of.
